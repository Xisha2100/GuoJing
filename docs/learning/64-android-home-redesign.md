# 64 · Android 状态引导首页与暖白朱红视觉重构

## 目标与页面结构

首页用于完成本机准备、查看当前指引状态，实际识别仍从目标应用内的“帮我”入口开始。采用暖白背景 `#FFF9F1`、朱红主色 `#9E2A2B`、深褐正文 `#241A18`；卡片圆角 24dp、页面边距 20dp、区块间距 16dp。标题和正文使用既有大字体系，主按钮至少 56dp 高，正文自然换行且不截断。

没有会话时，首页按“保存邀请码 → 开启界面指引服务 → 打开悬浮入口”提示下一步。已保存邀请码、已开通设备默认收起表单；准备就绪时引导用户打开目标应用。存在会话时，将当前阶段、完整指引、错误和结束操作放在准备事项之前。详细使用说明可展开，截图使用说明始终在页面中保留。

页面本身不创建识别任务，不添加应用选择器、手动截图或自动点击功能。就绪表示本地准备齐全，不代表已在线核验邀请码或设备授权。

## 状态和依赖

`AgentSessionPort` 是 UI 的会话控制接口，暴露不可变 `StateFlow`、挂起式邀请码保存、本机资料刷新、入口开关及结束操作。`AgentSessionController` 实现端口；`AgentViewModel` 不再依赖具体控制器。

`DeviceSetupState` 区分读取中、未保存、已保存待激活、已开通、授权受阻、读取失败。额度、排队和临时服务错误仅作为操作反馈，不覆盖设备开通状态。已收到的授权阻断在本进程内结束会话、刷新或读取失败后重试时仍保留；再次打开应用只能读取本地凭据，服务器仍在实际请求时校验授权。

`HomeUiState` 管理表单草稿、展开状态、保存中、保存反馈及关闭确认；`nextPreparation` 是可无 Android 运行时测试的优先级映射。界面拆分为首页组合、摘要/任务卡、准备事项/表单和主题。

## 邀请码与关闭交互

- 草稿仅存于 Activity 的 ViewModel 内存，旋转后保留，不使用 `SavedStateHandle`、Bundle、日志或额外磁盘存储保存草稿；进程退出后未保存草稿不恢复。
- 保存操作返回 `Saved` 或 `Failed`，成功后才清空并折叠；失败保留草稿并在表单处解释原因。处理期间禁用重复提交和修改，取消异常继续传播。
- 控制器串行保护初始化、会话恢复、保存和启动之间的关键转换。即使发生 UI 与后台状态更新的时序差异，保存也会被控制器再次校验。
- 保存及本机资料刷新不会调用模型、激活或截图。邀请码仍仅进入原有加密设备存储。
- 会话期间禁用邀请码更换；关闭悬浮入口前明确确认其同时结束指引，取消不修改会话或入口。无会话时直接切换。

## 验证方法

```sh
cd android
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
./gradlew connectedDebugAndroidTest
```

JVM 回归覆盖准备优先级、保存失败/取消/重复、初始化与恢复竞态、授权与临时错误分离、ViewModel 草稿保留及关闭确认。Compose 测试覆盖首次配置、已保存待激活、已开通、服务断开、入口关闭、保存反馈、各会话阶段、关闭确认、窄屏与 2 倍字号的完整文本及操作可达性。

截图测试使用本地虚构状态，生成应用私有目录下的 `home-normal.png` 和 `home-large-font.png`，用于实际模拟器渲染检查。这些 PNG、APK、构建缓存和模拟器数据不进入版本控制。不需要新增依赖、后端协议或数据库迁移。
