# 61 云端试点：设备准入、任务边界与恢复

2026-09-27 完成本模块的代码与离线回归。目标是杭州单 ECS 上最多 10 台受邀设备、约 1–3 人同时使用。外部 ECS、私有 OSS、域名、真实模型与真机验收按部署手册执行。

设备邀请码只存 SHA-256 摘要，有效期 7 天且一次兑换；本机随机秘密经 Android Keystore 加密，服务端也只保存摘要。兑换对相同安装 UUID 和秘密幂等。设备 ID 与会话关联，每次会话、run、查询、取消及 SSE 都重新检查 Bearer 凭据、设备状态和会话 token。停用设备后现有请求被拒绝，后台维护协程在最迟 15 秒内取消其任务。

额度采用 SQLite `BEGIN IMMEDIATE` 串行预留，同一设备同时只能有一个 `reserved/started` 任务。预留记当日北京日期，未实际开始模型就结束时退回；模型首次调用前的回调把预留改为 `started`。同一请求编号返回已有任务，不自动重跑失败任务。新的模型执行用新编号单独计数。每天 50/300 是次数防护，还须靠 token 汇总和实测模型价格估算成本。

工作协程把单个任务放在子任务里等待，取消子任务不会杀掉处理队列的协程。队列项有 30 秒截止时间且可删除，截图缓冲清零；沙箱创建、分析限 90 秒，销毁额外限 5 秒。模型调用回调将主/子智能体总调用数限制在 12 次。步骤、会话进度、任务终态一次数据库事务提交。单进程在恢复未完成任务与清理容器之前取得与 SQLite 路径关联的独占锁。

生产进程仅监听 127.0.0.1。Nginx 将 HTTPS 请求以 HTTP/1.1 透传，关闭上传与 SSE 缓冲和缓存。后端在读体前验证设备并按实际字节限制为 12 MiB。`/ready` 不调用模型，检查磁盘、迁移、Docker、镜像和后台协程；容器清理失败停止新分析。会话创建 24 小时后不可访问，每分钟清理，SQLite 删除后截断 WAL。备份仅序列化 `devices`、`device_invitations`、`daily_usage` 和全站额度设置，使用 ECS RAM 角色发往杭州私有 OSS；恢复到空数据库后强制暂停分析。

测试覆盖并发配额、跨设备越权、取消后继续、异常时事务回滚、超时释放截图、重启额度恢复、备份隐私与恢复暂停、10 台设备过载。真实 Docker 容器的 cgroup、网络、只读根和文件读写有显式集成测试与上线脚本门禁；真实模型与两台真机是独立的上线门禁。不要用合成通过率代替真实验收。

后续可靠性回归修复了两个恢复边界：每个 SSE 连接持有自己的通知事件，一个连接退出不会让其他连接失去实时更新；Android 恢复旧任务遇到 404 时清除过期会话并重新显示浮动入口，任务终态中的额度错误也显示对应提示。真实 Docker 集成测试发现 `network_disabled` 参数仍产生 `bridge` 模式，改用显式 `network_mode="none"` 后，容器的网络、cgroup 限制与文件读写检查通过。云端 rootless Docker 仍需按部署手册在 ECS 上单独验收。
