# 模块 18：无模型基础指引目录

## 1. 目标

没有已录制教程时，产品仍应给出安全的第一轮帮助。本模块把基础指引做成可替换的 `GuidanceCatalog`，而不是把大段文案写进 ViewModel 或 Agent prompt。

## 2. 目录边界

`DefaultGuidanceCatalog` 只发布三步通用说明：确认页面、遇到敏感页面暂停、回到老牌子补充问题。它不假装知道用户当前点击了哪个按钮，也不返回坐标、手势或 Accessibility 命令。

录制教程路由的行为相反：由于当前上传契约已经丢弃截图，系统不能匹配页面，必须进入人工复核。这是“宁可暂停，也不猜错”的产品原则。

## 3. 可替换设计

`GuidanceCatalog` 是一个小端口，未来可以由数据库中的已审阅模板实现。处理器依赖这个端口，领域对象只看到最终的不可变 `HelpRequestGuidance`。因此替换目录不会让 UI 依赖存储或模型 SDK。

## 4. 危险指引

领域层会拒绝支付、转账、发红包、密码、验证码、账号删除等危险操作词。这个检查位于 `HelpRequestGuidanceStep`，所以管理员接口、测试 fixture 和未来 Agent 都必须遵守，不是只有网页按钮遵守。

## 5. 与原始功能规划的关系

目录是“没有录制教程时的基础指引”最小闭环，适用于拍照、电话、导航等普通场景的通用确认流程。它不是替代微信支付或红包等具体教程；具体流程仍需录制教程、页面证据和风险等级共同支持。
