# 模块 15：OCR 隐私区域建议与逐项确认

## 1. 本模块解决的问题

模块 14 已经能在本机识别文字，但“识别到文字”不等于“可以自动遮挡”。本模块把 OCR 结果转换为用户可审核的建议：

```text
本机 OCR 原文
  → 敏感模式分类器
  → 类型 + 置信度 + 归一化矩形
  → 橙色候选框
  → 用户选择遮住 / 不是隐私
  → 已接受区域变成黑色脱敏框
```

分类器输出不包含 OCR 原文，因此 ViewModel 和 Compose 状态不会保存电话号码、订单号或余额文本。

## 2. 为什么建议不能自动应用

OCR 可能把普通数字识别成订单号，也可能漏掉姓名、头像或二维码。自动遮挡会带来两个问题：

1. 用户不知道哪些像素已经改变，无法判断求助截图是否仍然有用；
2. 错误分类会让用户以为“系统已经完成隐私检查”，形成危险的安全错觉。

因此编辑状态加入了一个确定性门槛：

```text
有 Pending 建议 → 不能生成脱敏副本
Accept           → 加入黑色遮挡区域
Reject           → 保留原图，不遮挡
所有建议已决定   → 才能继续手动框选或生成副本
```

这和 Java 后端的审批状态机相同：候选记录和最终决策是两个状态，不能在 DTO 映射时偷偷把候选变成已批准。

## 3. 敏感分类器的边界

`OcrPrivacySuggestionClassifier` 是本地、保守、可解释的规则分类器。当前识别：

- 手机号、邮箱、身份证号、银行卡号；
- 验证码、余额/金额、订单号/物流信息；
- 姓名、联系人、收货人、地址等标签。

规则只返回 `SensitiveTextKind`，不返回匹配到的原文。置信度由规则强度和 OCR provider 置信度相乘得到，不能当成隐私安全证明。二维码、头像和没有文字的姓名仍然需要用户手动框选。

## 4. 状态如何保证安全

`ScreenshotHelpUiState.Editing` 新增 `privacySuggestions`：

```text
Pending   → 橙色候选框，显示“遮住这处 / 不是隐私”
Accepted  → 转成 NormalizedRedaction，预览显示黑色区域
Rejected  → 候选框消失，记录只留本次内存状态
```

`canSanitize` 同时要求：

- 问题不为空；
- 没有 Pending 建议；
- 至少有一个手动/建议遮挡区域，或用户明确确认没有敏感内容。

如果 OCR 失败，状态显示可理解的提示，但不阻塞手动框选。OCR 是辅助能力，不应成为用户完成隐私处理的单点故障。

## 5. 原文生命周期

导入截图后，ViewModel 在一个协程中调用 provider：

```text
provider.recognize(screenshot)
  → classifier.classify(blocks)
  → 丢弃 blocks
  → Editing(privacySuggestions)
```

`OcrTextBlock` 不进入 UI 状态，建议对象只保存类别、位置、置信度和决策。原始 `InMemoryScreenshot` 仍由 privacy 模块管理，返回、换图、取消和 ViewModel 销毁时继续清零。

## 6. UI 交互取舍

- 橙色框代表“系统建议”，黑色框代表“已经确认的遮挡”；两者不能混淆。
- 每一条建议都有明确的正向和反向按钮，避免只提供一个容易误触的确认动作。
- 未处理建议会显示阻塞说明，而不是让用户只看到一个灰掉的按钮。
- 建议类型使用“电话号码”“余额或金额”等老年用户容易理解的词，不显示原始 OCR 文本。

## 7. 测试

JVM 测试覆盖：

- 手机号和余额分类；
- 地址、订单号标签分类；
- 无边界或过小矩形被丢弃；
- 原文不会出现在建议对象的 `toString()` 中；
- Pending 建议阻止脱敏，Accept 后加入遮挡，Reject 后可用“确认没有隐私内容”；
- OCR 失败仍可手动完成脱敏。

Pixel 7 Compose 测试覆盖候选建议的可见性和逐项确认按钮。真实 ML Kit 识别仍由模块 14 的设备测试覆盖。

## 8. 当前限制与下一模块

- 规则分类器不是完整的中文实体识别器，不能保证发现所有姓名、地址或二维码。
- 候选建议最多展示 20 条；如果识别结果超过上限，UI 会明确提示并阻止发送，避免把静默截断误认为已经检查完毕。
- 建议目前只存在于本次编辑会话，不写入后端，不用于训练。
- 截图求助后端仍只返回接收收据，没有 OCR 结果或基础指引答案。

下一模块可以定义“求助处理结果”契约，让用户查询服务端处理状态；在接入 OCR/视觉 Agent 前，仍需保持图片生命周期、显式发送和结果安全策略分离。
