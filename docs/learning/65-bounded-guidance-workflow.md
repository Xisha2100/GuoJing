# 65 · 受限视觉工作流与会话恢复

完成日期：2026-10-31。依据[重构方案](../deepagents-refactor-plan-2026-10-31.md)实施 P0–P3 的代码与离线验证。Deep Agents 保持实际安装及锁定的 **0.7.32**。用户交互、HTTP 路径、鉴权、GET/SSE、幂等编号和 `schema_version=1.0` 的字段集合不变，没有数据库迁移。

## 两种实现与默认值

新增 `GUOJING_GUIDANCE_ENGINE`，只接受以下两值；未知值在配置加载时失败。

| 引擎 | 调用和资源 | 当前用途 |
|---|---|---|
| `legacy_hardened` | 成功路径 5 次；保留每轮独立 Docker 沙箱 | 默认及回退路径；已修复工具权限、委派和审校闭环 |
| `bounded` | 视觉候选 → 独立视觉复核，正常 2 次；一次措辞修订后再次复核，最多 4 次；无需 Docker | 显式启用以进行真实模型对照 |

两者都复用当前视觉模型配置，不在同一请求中切换供应商或重跑另一引擎。运行共用原有 90 秒截止时间、12 次调用后备上限、单次 2,048 输出 tokens 和设备配额；第一次模型调用开始只扣一次设备次数。拒绝、无效结构和无法确定返回原有 `cannot_determine`；传输失败、超时、取消及调用总预算继续使用现有任务状态和错误码。

## 内部边界

`domain/guidance_policy.py` 定义不可变候选和审校对象。主机对完整候选的规范化内容计算 SHA-256，审校必须回显一致标识；通过后直接返回候选的原始领域对象。状态、指令、目标、置信度、依据或风险发生变化都会产生新标识。候选和审校只属于当前调用栈，不保存到数据库，也不加入 HTTP 响应。

接纳要求结构严格合法、有限数值、正面积整图坐标、既有置信阈值、可见证据、普通风险和对应的目标/完成支持。中文规则仍由确定性规则检查。金融、不可逆或未知风险阻断；关键词补充拦截支付、转账、删除、授权和验证码等指引，但不把关键词或模型分类宣称为完整风险识别保障。

只有复核确认视觉依据与风险已支持、问题仅是措辞时，才可修订一次。修订使用同一张图，产生新候选并重新复核；第二次否决直接结束。结构错误不启动隐藏的格式修复循环。相邻两轮图片摘要相同，且继续指引的完整文字与目标框也相同，领域规则将其转为无法判断；该规则只识别这一狭窄的无进展情形，不声称可以检测任意页面循环。

`application/agent/context.py` 保留最近 6 条完整指引，序列化历史最多 4,000 字符，超出时移除整条旧记录；不截断条件或否定词，不调用模型总结。上下文明确标记为“之前发出的指引”，用户点击下一步也不被当作已执行成功的证明。

`infrastructure/agents/workflow.py` 使用显式异步流程组合两个真实 Deep Agents 图。每阶段只可调用一次模型，使用 `ToolStrategy(..., handle_errors=False)`。候选和复核各自接收当前图片及必要文本，不继承对方完整对话。每轮新建图与 StateBackend；模型客户端可复用，图状态、图片和预算不可跨 run 共享。

## Deep Agents 0.7.32 适配

`harness.py` 使用公开 `register_harness_profile`，按完整 `openai:<model>` 键注册共同最低权限。注册是进程级行为，因此只在构造时缓存注册，不按请求切换。关闭隐式通用子智能体、模型摘要和默认文件工具；保留上游要求的 FilesystemMiddleware，但拒绝读写 permissions，关闭人类消息、二进制及工具结果的文件卸载。

`GuidanceToolGuard` 在调用模型前筛选工具，并在返回后及工具执行前再次检查。每个新节点只允许自己的结构化输出。即使模型虚构未展示的 `execute`、`read_file`、`write_file`、`task` 或未来工具，也不能执行。没有输出工具、多个输出、错误类型、未知枚举和非有限值都拒绝。

旧主模型只允许依次委派 `ui-analyst` 和 `guidance-reviewer`；执行前检查名称、完整参数、阶段和唯一调用 ID。审校任务由主机重新组装冻结候选、分析和标识。Fork 的子节点以同名 guard 替换继承的主节点权限，禁止再次委派。审校仍然只看文字，否决即阻断；最后的主模型输出必须逐字段等于受审候选。

所有节点、修订与异常路径保持 `tracing_context(enabled=False)`，不设置 checkpointer。真实图测试替换模型生成函数，实际执行已安装框架图，不 mock `create_deep_agent`。

## 资源与日志

组合根仅在 `legacy_hardened` 模式创建 Docker 注册器。协调器允许无沙箱运行，仍保留会话串行化、队列图片清理、取消和关闭逻辑。`bounded` 不上传图片文件，其 `/ready` 不检查 Docker；没有模型配置时仍不可就绪。`sandbox_check` 根据引擎选择资源门禁，旧模式继续验收真实内核限制。默认初始化脚本仍为旧模式及回退准备 Docker。

`ModelUsage` 和每轮数值日志增加阶段调用数、输入/输出 tokens、耗时、队列等待、沙箱准备/清理、引擎与提示词版本、修订次数和固定拒绝代码。`/internal/status` 外部字段未扩展。日志不输出目标、控件文字、候选、截图、Base64、完整消息或原始异常正文；相应 API 测试检查日志内容。

队列和 Android 可变图片缓冲在成功、异常及取消路径尽力擦除。不可变 bytes、Base64 和 SDK 内部副本无法保证物理清零；实现减少留存和复制，不承诺擦除全部进程内存。

## Android 恢复与截图

沿用既有 `AgentSessionPort`、Repository、截图、覆盖层、语音和存储端口；首页、输入框、目标框和动作按钮布局未改动。

| 模块 | 职责 |
|---|---|
| `SessionReducer` | 纯状态完成规则及会话代次、session/run 身份校验 |
| `RunRecovery` | 查询已有任务、SSE 转轮询、校验每个响应；不截图、不上传、不取消已找到任务 |
| `ConfirmedCapture` | 一次用户动作对应一次截图；先持久化 turn ID，再核对窗口/几何并上传；负责清理图片缓冲 |
| `AgentSessionController` | 组合端口、状态流、展示与朗读；按代次拒绝过期异步结果，用互斥锁串行化本地会话写入/清除 |

上传响应丢失时优先按 turn 找回任务；找回后继续监听或读取终态，不把它取消后重新截图。超时后的用户重试也先读取原任务。旧任务的 `continue` 结果仅恢复背景，仍需用户重新识别当前画面，不能重放旧框。

窗口 ID 只作为本次内存中的截图几何信息，不扩展网络协议。截图前后、持久化 turn ID 后及结果展示前核对包名、窗口 ID、旋转和显示尺寸。窗口或几何变化阻断当前上传/展示；这些元数据不能证明同一窗口的内容完全没有变化。会话结束或新会话开始后，迟到网络响应和迟到存储写入不会重新展示或朗读旧结果。

目标确认前零截图/零请求、下一步才可重截、不遍历节点文字、不执行手机动作、目标框不可触摸及完整文字/TTS 同步规则保持不变。
